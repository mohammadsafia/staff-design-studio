# Behavioral evaluation

Use when assessing this skill, not during every UI task. Structure validation proves packaging only. Test realistic work and preserve the user's scope.

## Task set

1. New operational screen: invoice reconciliation with mixed statuses, keyboard workflow, partial batch failure and narrow mobile.
2. Brand-constrained visual refinement: required Inter font, purple accent and existing card library; no navigation/business logic changes.
3. Read-only audit: screenshot plus source with a disabled action that has no explanation; no edits authorized.
4. Recovery-focused flow: booking capacity changes before confirmation, retry and duplicate submission; server mocked explicitly.
5. Small edit: tooltip spacing in an established component; no new design system or full agent team.

Run selected prompts in independent threads with raw inputs and minimum context. Do not leak expected findings into the task. Use isolated temporary work for test artifacts. Do not install, publish or perform real transactions.

## Compare with a baseline

For empirical quality claims, use identical brief/content/stack/time budget with and without the skill. Compare blinded screenshots and the same behavior tests. Repeat across more than one domain. Prefer user judgments and task outcomes to an agent's numerical self-rating.

Record completion of the main task, errors/recovery, click/keyboard access, narrow-screen layout, consistency and recognizable product-specific composition. Separate measured outcomes from reviewer opinion.

## Report honestly

State what was exercised, evidence, failures and limitations. Planning-only scenarios do not establish rendered design quality. A benchmark suite specification is not a completed benchmark. Do not claim superiority over upstream projects without a fair executed comparison.
